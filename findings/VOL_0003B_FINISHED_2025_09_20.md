# VOL_0003B — Density Probe + Analytic Sphere Baseline (Finished)

## Summary
- Added an analytic sphere density fill shader and a density probe debug mode.
- Purpose: establish a known-good, high-contrast density field and a simple readout to validate sampling and ray entry points.

## Changes
- Shaders
  - `shaders/vol/density_fill_sphere.hlsl`: compute shader to fill a solid sphere in the 3D density UAV. Center/radius/density are passed via constants.
  - `shaders/vol/ray_march_cs.hlsl`: new debug mode 3 (DensityProbe). Writes a single grayscale sample at the entry point to the volume.
- C++
  - `DensityVolume.h/.cpp`:
    - Added `FillAnalyticSphere(cmdList, XMFLOAT3 centerUVW, float radiusUVW, float densityValue)`.
    - Expanded fill root signature constants from 4 → 8 to pack sphere params (cx, cy, cz, r, density, pad...).
    - Loads `density_fill_sphere.dxil`, creates compute PSO from the texture’s device, dispatches in (dim+7)/8 groups, inserts UAV barrier.
  - `App.cpp`: F4 cycles debug: Off → RayDir → Bounds → DensityProbe. Logs mode.
  - `CMakeLists.txt`: compiles `shaders/vol/density_fill_sphere.hlsl` to DXIL and adds it to `compile_shaders`.

## How to use
- For now, replace the procedural fill call with sphere fill in `renderFrameDXR` to validate:
  - Call `m_densityVolume->FillAnalyticSphere(cmdList, {0.5f,0.5f,0.5f}, 0.30f, 1.0f);`
- Press F4 until `DensityProbe` is logged. You should see a crisp circular silhouette where the ray first hits the sphere. Switch back to Off to resume marching.

## Difficulties encountered
- Include types: needed `#include <DirectXMath.h>` for `DirectX::XMFLOAT3` in `DensityVolume.h`.
- Creating PSO for on-the-fly shader: had to query the texture’s owning `ID3D12Device` via `GetDevice()` to create the compute PSO.
- Root signature constants: increased constant count to pack sphere parameters; otherwise only the first 4 values would be visible to the shader.

## PIX guidance (recommended now)
- Install PIX for Windows. Launch PIX, set target to `build-vs2022b/Debug/PlasmaDX.exe` with working dir at repository root.
- Environment: set `PLASMADX_DISABLE_DXR=1` (compute-only).
- GPU capture flow:
  - Start capture; move camera; press F4 to RayDir → Bounds → DensityProbe.
  - Inspect the compute dispatch for sphere fill (ThreadGroupCount ≈ 16×16×16 for a 128³ volume) and for the marcher (≈120×68×1 at 1920×1080 with 16×16 threads).
  - In the event view, open constant buffers for the marcher; verify values: `g_invViewProjMatrix`, `g_volumeMin/Max = [-1,1]`, `g_screenSize`, and transport params (densityScale, absorption, stepSize, maxSteps, exposure).
  - Use Resource History on the density 3D texture and HDR target. Check UAV barriers after writes and HDR transition to SRV before composite.
- Expected findings based on `pix/GPU 2.txt` and `pix/GPU 6.txt`:
  - Density fill dispatch present (~16×16×16) followed by a UAV barrier.
  - Marcher dispatch present (~120×68×1) with a UAV barrier on HDR target, then HDR UAV→SRV transition, then composite.
